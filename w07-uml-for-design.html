Design

Drawing before building

Why draw a diagram when the code is the truth?

Because a diagram is cheaper

  • You can throw away a bad design in ten minutes, not ten days
  • It is the fastest way to argue with two teammates
  • It shows structure the code hides across forty files
  • In the project report, it is how you justify your design

Draw to think and to communicate.

Not to document what you already built, in the week before delivery.

One

Class diagrams

The structure of your game

Notation you actually need

RelationshipNotationMeans
Generalisationsolid line, hollow triangleextends / implements
Associationsolid lineA knows about B
Aggregationhollow diamondA has B; B survives A
Compositionfilled diamondA has B; B dies with A
Dependencydashed arrowA uses B transiently

Aggregation or composition?

Aggregation ◊

Arena ◊— Hero

The hero could exist in another arena. Destroy the arena, the hero is still a valid object.

Composition ◆

Hero ◆— Position

The position has no meaning without the hero. It is created and destroyed with it.

Multiplicity

  • 1 — exactly one
  • 0..1 — optional
  • * or 0..* — any number
  • 1..* — at least one
  • Put it on both ends. “Arena 1 — * Element” says a lot in six characters.

The diagram above, as code

public abstract class Element {
    protected final Position position;      // composition
    public abstract void draw(GUI gui);
}

public class Hero extends Element { ... }   // generalisation
public class Wall extends Element { ... }
public class Monster extends Element { ... }

public class Arena {
    private final List<Element> elements;   // aggregation, 1 -- *
}

If your diagram and your code disagree, the diagram is wrong.

What should not be on a class diagram?

Leave it out

  • Every getter and setter
  • Every field, when the point is the relationships
  • Classes that are not part of the argument you are making
  • String, List, and the rest of the JDK

A diagram with forty boxes communicates nothing.

Draw the six that matter for the point you are making.

Two

Sequence diagrams

A class diagram shows what exists. What shows what happens?

One keypress, end to end

Reading it

  • Boxes at the top: objects, not classes — :Arena, not Arena
  • Vertical dashed line: the lifeline. Time goes down.
  • Thin rectangle: activation — this object is on the stack
  • Solid arrow: a call. Dashed arrow: a return.
  • Use it for the two or three interactions that are actually subtle

Sequence diagrams are where you notice

that your controller is talking to seven objects.

Three

State diagrams

Your game has a menu, a running state, a pause and a game-over screen. Where does that live in the code?

A state machine

Why draw it

  • It makes the illegal transitions visible — can you pause from the menu?
  • Each state becomes a class (the State pattern, week 9)
  • Each transition becomes a test
  • The diagram is the test plan

From diagram to tests

@Test void escFromRunningPauses() {
    Game game = new Game(new RunningState(arena));
    game.processKey(ESC);
    assertInstanceOf(PausedState.class, game.state());
}

@Test void escFromMenuDoesNothing() {
    Game game = new Game(new MenuState());
    game.processKey(ESC);
    assertInstanceOf(MenuState.class, game.state());
}

Practice

Which diagram, when

Three diagrams, three questions

DiagramAnswersUse it when
ClassWhat exists and how is it related?Arguing about structure — always
SequenceWho calls whom, in what order?One interaction is subtle
StateWhat can happen next?An object has modes

Tooling

  • PlantUML or Mermaid — text, diffable, lives in the repository next to the code
  • IntelliJ can generate a class diagram from your code — useful as a mirror, not as a design
  • A photograph of a whiteboard is a perfectly good early design
  • Do not spend an evening in a drawing tool. Spend it on the design.

Take away

  • Draw to decide, not to document
  • Composition dies with the whole; aggregation does not
  • Six boxes that make the argument beat forty that do not
  • A state diagram is a test plan in disguise
